# Lupi bounded render backend

This service completes the existing Cloudflare Worker **legacy-v0** HTTP
handoff with a deliberately narrow production surface. It does not activate or
claim the Render Artifact V1 executor contract.

The container builds `apps/web`, serves that exact build on loopback, and drives
the typed `window.__lupiViewerMcp` bridge with Playwright. It has no dependency
on `lupi.live` or any other production website; the browser context blocks all
non-loopback network requests. The recovered implementation
shape comes from `origin/shop-route`; commerce, colorways, PCA orientation,
transparent matting, and DOM-selector automation were intentionally excluded.

## Supported request

The only render route is authenticated `POST /render`. `GET /health` is
unauthenticated and reports only the public protocol/capability and lane state.
Every other route is rejected.

The request body is capped at 256 KiB and must have exactly this envelope:

```json
{
  "protocol": "lupi.renderer-request.legacy-v0.1",
  "jobId": "job-v0-<worker-generated UUID v4>",
  "request": {
    "molecule": {
      "inputType": "template",
      "input": "Caffeine"
    },
    "asset": {
      "format": "png",
      "width": 1024,
      "height": 1024,
      "transparent": false,
      "inline": false,
      "maxInlineBytes": 8388608
    },
    "viewer": {},
    "rendererVersion": "lupi-authenticated-png@2026-07-20"
  }
}
```

`jobId` is the exact `job-v0-` UUID v4 generated by the Worker. The backend
validates that shape and returns the same string without rewriting it. Request
content identity remains the Worker's separately computed `requestKey`.

The bounded profile accepts:

- local `template` inputs: Water, Benzene, or Caffeine;
- `procedural` SC/BCC/FCC inputs with 1–100,000 atoms, one validated element,
  and optional spacing from 0.1 through 20;
- opaque PNG only, at integer dimensions from 64 through 2048 pixels;
- an empty legacy `viewer` object only.

The normalized request's `asset.inline` and `asset.maxInlineBytes` delivery
preferences are validated but intentionally ignored. The backend always needs
the browser bytes in-process and always returns them to the Worker.

## Execution and response truth

One serialized lane owns one browser page. For each request it executes only:

1. `lupi.reset_viewer`
2. `lupi.generate_molecule`
3. `lupi.set_viewer` with bonds, cell, and axes disabled so deterministic
   raster capture never depends on asynchronous topology
4. `lupi.set_background` with a fixed opaque, motion-paused background
5. `lupi.export_asset` for exact PNG dimensions

The service captures and validates the complete browser export receipt,
including its byte payload, data URL, dimensions, byte length, and artifact
digest. It then decodes the PNG and re-encodes it with the exactly pinned
`sharp@0.33.5` as 8-bit RGB PNG (IHDR color type 2), stripping alpha and metadata.
The response is:

```json
{
  "protocol": "lupi.renderer-response.legacy-v0.1",
  "jobId": "job-v0-<same exact UUID>",
  "asset": {
    "mimeType": "image/png",
    "width": 1024,
    "height": 1024,
    "byteLength": 12345,
    "dataBase64": "<canonical padded base64>"
  },
  "browserReceipt": {
    "provenanceOnly": true,
    "byteScope": "pre-rgb-reencode-provenance-only",
    "identifiesResponseAsset": false,
    "format": "png",
    "filename": "...",
    "mimeType": "image/png",
    "width": 1024,
    "height": 1024,
    "byteLength": 12000,
    "contractVersion": "...",
    "sourceContentDigest": "...",
    "specId": "...",
    "rendererFingerprint": "...",
    "artifactKey": "...",
    "artifactDigest": "..."
  }
}
```

The `browserReceipt` identities describe only the browser-export bytes before
Sharp re-encoding. `identifiesResponseAsset: false` is deliberate: none of
those identities is claimed to identify the returned PNG. The Worker remains
responsible for validating and digesting the returned bytes before storage.

## Build and run

Build from the repository root with the exact revision embedded in the co-built
viewer:

```bash
docker build \
  -f apps/render-backend/Dockerfile \
  --build-arg LUPI_BUILD_SHA="$(git rev-parse HEAD)" \
  -t lupi-render-backend .
```

Run with a secret supplied by the deployment platform:

```bash
docker run --rm -p 8080:8080 \
  -e RENDERER_TOKEN='<strong-random-secret>' \
  lupi-render-backend
```

Startup fails before either listener opens when `RENDERER_TOKEN` is absent or
blank. `RENDER_DEADLINE_MS` defaults to 85 seconds (inside the Worker's
90-second handoff deadline) and may be set only from 5 through 300 seconds.
Deploy with platform concurrency 1; the application also
serializes requests so stateful browser work never overlaps within an instance.

## Focused boundary tests

```bash
npm test
```

The Node-native suite covers protocol normalization, fail-closed token handling,
and the HTTP authentication/body boundary through an injected render lane. It
does not launch Chromium or execute a molecular render.

`.github/workflows/deploy-render-backend.yml` builds this Dockerfile from the
repository root and deploys the exact Git SHA. It reuses repository secrets
`GCP_PROJECT_ID`, `GCP_REGION`, `GCP_SERVICE_ACCOUNT`, and
`GCP_WORKLOAD_IDENTITY_PROVIDER`, and additionally requires
`GCP_SERVICE_NAME_RENDERER`. The regional Artifact Registry repository
`cloud-run-source-deploy` and Secret Manager secret `lupi-renderer-token` must
already exist; the Cloud Run runtime identity needs access to the latter.

## Cloud Run authentication boundary

Cloud Run must use `--allow-unauthenticated` so the Cloudflare Worker can reach
the HTTPS service without obtaining a Google identity token. That IAM setting
only removes Cloud Run's platform-level Invoker challenge; it does **not** make
the render application anonymous. The container refuses to start without
`RENDERER_TOKEN`, exposes only `GET /health` without credentials, and compares
the `Authorization: Bearer ...` value before reading or executing any
`POST /render` request. Every other route is rejected.

The production workflow binds `RENDERER_TOKEN` from Google Secret Manager
secret `lupi-renderer-token:latest`. This renderer credential is independent of
the caller-to-Worker `LUPI_MCP_SHARED_SECRET` and must never be returned to an
agent. Candidate promotion deliberately probes only unauthenticated
`GET /health`; Cloudflare-to-renderer authenticated execution is proven in the
separate Worker live-evidence lane.
